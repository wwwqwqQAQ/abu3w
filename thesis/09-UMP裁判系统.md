# 第九章 UMP裁判系统

## 9.1 UMP系统的设计思想

UMP（Unified Match Policy，统一裁判策略）系统是阿布量化中最具创新性的模块。其设计理念源自体育比赛中的裁判制度：买入因子产生交易信号（就像球员射门），UMP系统扮演裁判角色，判断这个"射门"是否有效——信号是否应该被执行。

系统采用"主裁判+边裁判"的双层架构：

- 主裁判（Main Referee）：使用高斯混合模型（GMM）无监督聚类，从全局角度识别"不好的交易模式"。主裁判负责把握大局——把那些在所有维度上都看起来不对劲的交易信号拦截下来。

- 边裁判（Edge Referee）：使用相似度加权投票机制，从局部角度进行精细判断。边裁判负责捕捉主裁判可能遗漏的"边缘球"——在全局统计上不算典型，但在局部特征上类似于历史亏损交易的信号。

在体育比赛中，主裁判的决定优先，边裁判的意见作为补充。在UMP系统中，两者是并联关系——任何一个裁判判定拦截，信号就被拦截。这种"宁可错杀，不可放过"的保守设计面向的是实际交易中的非对称性：一次重大亏损可能需要多次盈利才能弥补，因此减少亏损比增加盈利更重要。

## 9.2 UMP基础设施

### 9.2.1 类型标记

BuyUmpMixin和SellUmpMixin是两个类型标记混入类，分别设置_ump_type_prefix为'buy_'或'sell_'。每个UMP裁判是其中一个类型的专属裁判——买入裁判只拦截买入信号，卖出裁判只拦截卖出信号。

### 9.2.2 模型缓存管理

CachedUmpManager是一个共享的内存缓存管理器，用于存储已训练的UMP模型。它使用普通字典（或可选WeakValueDictionary）存储序列化后的模型对象。当多个策略需要使用同一个UMP裁判时，缓存的命中避免了重复的文件读取和反序列化开销。每个UMP通过dump_file_fn()声明其pickle文件路径，CachedUmpManager在缓存未命中时从磁盘加载。

### 9.2.3 装饰器架构

ump_main_make_xy装饰器统一了所有主裁判的数据预处理流程：

1. 移除result==0的交易（未平仓/持仓中的订单）

2. 将-1（亏损）转换为0（非盈利），实现二分类标签。这个转换将多分类问题（大赚/小赚/小亏/大亏）简化为二元分类（盈利/亏损），使GMM聚类能够聚焦于"亏损模式识别"这一核心任务。

3. 可选地对特征矩阵应用StandardScaler标准化

ump_edge_make_xy装饰器统一了边裁判的数据预处理：

1. 同样移除result==0的交易

2. 额外过滤profit==0的交易（无实际盈亏的交易对相似度判断没有信息量）

3. 设置self.y为前两列（profit和profit_cg），而非单一的盈利/亏损标签。这样边裁判可以在相似度投票时使用连续的利润幅度信息。

## 9.3 主裁判算法：GMM聚类+暴力搜索优化

主裁判的核心算法包含训练和预测两个阶段。

### 9.3.1 训练阶段：多分量GMM聚类



训练算法遍历多个高斯混合模型的分量数（component count），默认范围为40到84个分量（步长为1）。当训练数据超过50000条交易记录时，分量范围等比放大。选择45个分量（即45个可能的高斯分布）是一个有趣的数值——它远大于典型的金融数据聚类数（通常3-10个），反映了系统设计者对交易模式的复杂性有充分的认识：市场行为不能用少数几个清晰可分的模式概括，而是存在大量边界模糊、相互重叠的"微模式"。使用大量分量可以捕捉到这些细微的亏损模式。

对每个分量数c：
1. 训练一个GaussianMixture(n_components=c)模型。GMM假设数据由c个多元正态分布混合生成，通过EM（Expectation-Maximization）算法迭代估计每个分布（分量）的均值向量、协方差矩阵和混合权重。EM算法[^ump_2]的E步计算每个样本属于每个分量的后验概率，M步根据这些概率重新估计模型参数。

2. 使用训练好的GMM对所有训练样本进行聚类预测（assign到概率最大的分量）。

3. 对每个聚类（分量），计算交叉表（contingency table）：pd.crosstab(cluster, result)，统计该聚类中盈利交易和亏损交易的数量。

4. 筛选"坏聚类"：亏损率（loss_rate）超过阈值的聚类。阈值默认为0.65，即如果一个聚类中有65%以上的样本是亏损交易，则标记为"坏聚类"。0.65这个阈值是一个非对称设计——它远高于随机概率0.50，意味着系统只在"非常确信"某个聚类表现为亏损模式时才将其标记为"坏"。

当交易记录数超过1000时，不同分量数的GMM训练通过joblib.Parallel并行执行。

### 9.3.2 聚类度量

对每个被标记为"坏"的聚类，计算四个度量指标：

- lcs（loss count）：聚类中的交易样本数
- lrs（loss rate）：聚类中的亏损率
- lps（loss profit sum）：聚类中交易的利润总和
- lms（loss profit mean）：聚类中交易的平均利润

这些度量构成cprs DataFrame，索引为'分量数_聚类标签'的组合键，用于后续的暴力搜索优化。

### 9.3.3 全局优化：三维暴力搜索

brust_min函数使用scipy.optimize.brute在三维参数空间中进行暴力搜索：

参数空间：(lps_threshold, lms_threshold, lrs_threshold) 的三个取值范围的笛卡尔积。

目标函数：maximize improved_metric

```
improved = (effect_num / total_trades) * (loss_rate - win_rate)
```

(公式9-1)

这个复合目标函数的设计值得深入分析。它将"拦截效率"分解为两个因子的乘积：(1) effect_num/total_trades——被拦截的交易占总交易的比例（覆盖率），(2) loss_rate - win_rate——被拦截交易中亏损率与盈利率的差值（区分度）。使用乘积而非加权和的好处是它自然地平衡了覆盖率与区分度——一个覆盖率很高但区分度很差的方案（拦截了大量交易但亏损率没有显著高于整体）和一个区分度很好但覆盖率太低的方案（只拦截了极少量的极端情况）都不会得到高分。

brute函数在参数空间中按固定步长均匀采样（网格搜索），计算每个网格点的目标函数值，选择最大值对应的参数组合。搜索结果缓存在self.brust_cache字典中，避免重复计算相同的参数组合。

### 9.3.4 模型序列化

dump_clf()方法将训练后的模型保存到磁盘。它仅保存经过暴力搜索筛选后的"有效"GMM模型（即那些包含至少一个通过三维参数筛选的"坏聚类"的模型）。保存的数据结构为：{分量数_聚类标签: (GMM模型对象, 聚类标签)}。未通过筛选的模型不会被保存，这节省了存储空间和加载时间。

### 9.3.5 预测阶段

predict(x, need_hit_cnt=1)方法接收一个新的交易信号的特征向量x：

1. 加载clf_cluster_dict缓存（分量数_聚类标签 → (GMM模型, 聚类标签)的映射）。

2. 对字典中的每个(模型, 标签)对，调用model.predict(x)获取x所属的聚类标签。

3. 如果预测的聚类标签与存储的"坏聚类"标签匹配，命中计数器加1。

4. 如果hit_count >= need_hit_cnt（默认1次），返回1（拦截信号）。

need_hit_cnt=1意味着只要有一个GMM模型判定该交易属于"坏聚类"，信号就被拦截。由于系统中保存了45个不同分量数的GMM模型，每个模型都是独立训练的，因此1次命中规则相当于45个独立裁判的并联投票——任何一个裁判认为有问题就拦截。这是一个极其保守的设计。

## 9.4 边裁判算法：相似度加权投票

边裁判使用与主裁判完全不同的方法论。主裁判是"聚类→识别亏损群组"，边裁判是"找邻居→看邻居是赚是亏"。

### 9.4.1 训练阶段：三级分类

边裁判的训练过程非常简洁：

1. 按profit_cg（利润率）对所有历史交易进行排序。

2. 使用K_CG_TOP_RATE = 0.236将排好序的交易分为三类：

   - rk = -1：利润率最低的~23.6%（最大亏损）

   - rk = 0：中间的~52.8%

   - rk = 1：利润率最高的~23.6%（最大盈利）

0.236是1 - 0.618²（斐波那契比例的变体）——这是一个非对称的分类阈值，底部23.6%和顶部23.6%被抽出，中间大部分交易被归为"中性"。这种不对称分类在金融直觉上是合理的：大部分交易（中间52.8%）是"正常"的——赚一点或亏一点——只有两端是"显著优秀"或"显著糟糕"的。

注意一个重要的非对称处理：由于在大多数策略中，亏损交易的数量多于盈利交易，底部23.6%的实际交易数通常多于顶部23.6%。但算法没有对此进行调整（例如使用等样本量），而是有意保留了这种不均衡。这种"非均衡"处理使得"亏损模式"的样本数量多于"盈利模式"，在投票时亏损方的票数天然更多——这进一步强化了系统的保守倾向。

### 9.4.2 预测阶段：相似度加权投票

对一个新的交易特征x：

1. 将x与全部训练数据拼接，进行统一标准化。

2. 计算x与每个训练样本之间的欧几里得距离（pairwise_distances）。

3. 如果最小距离超过K_DISTANCE_THRESHOLD（0.668），返回中立（不做判断）。这个阈值确保只有当新交易与历史交易有足够的相似度时，裁判才做出判断。与历史交易差异太大的新交易超出了裁判的"经验范围"，不适合用相似度方法判断。

4. 选取最近的K_N_TOP_SEED（100个）邻居。

5. 对每个种子邻居，计算其与x的皮尔逊相关系数（通过ABuCorrcoef.corr_xy），得到相似度分数。

6. 过滤相似度低于K_SIMILAR_THRESHOLD（0.91）的邻居。只有与x高度相似（相关系数>0.91）的历史交易才能参与投票。

7. 加权投票：每个合格邻居按其相似度作为权重，朝其排名类别（rk=-1、0或1）投票。汇总每个类别的加权投票数。

8. 决策：如果某一方的投票权重超过另一方超过K_EDGE_JUDGE_RATE（0.618，黄金分割比例）的优势，做出相应的判断。例如，如果亏损方的投票权重是盈利方的1.618倍以上，则判定拦截。

0.618的黄金分割比例又一次出现在系统设计中。这个高于0.5的阈值确保了系统不会因为微小的投票差异就拦截交易——需要亏损方的投票显示出"统计上显著"的优势，才做出拦截决定。

### 9.5.3 裁判管理

ABuUmpManager是连接交易因子与UMP系统的桥梁。每个买入因子在初始化时创建一个AbuUmpManager实例。Manager通过@LazyFunc[^ump_8]装饰器在首次访问时惰性加载各裁判。

builtin_ump_block(ml_feature_dict)方法的工作流程：

1. 接收交易信号的ML特征字典

2. 检查各裁判的启用开关（由ABuEnv.g_enable_ump__*_block全局标志控制）

3. 对每个启用的裁判，检查其类型（buy_ump/sell_ump）是否与当前因子匹配

4. 调用匹配裁判的predict方法

5. 如果任一裁判返回拦截信号，则拦截该交易

用户可以通过append_user_ump()方法注册自定义裁判。自定义裁判可以是类（使用时动态实例化）或预实例化的对象，通过class_unique_id()进行缓存管理。自定义裁判支持replace_word_delegate_has_method方法——当用户自定义裁判需要特殊的命中计数规则时，可以通过该方法替换默认的delegate方法。

## 9.6 UMP系统的设计特征

UMP系统体现了几个核心设计特征：

1. 非均衡性：从聚类亏损率阈值（0.65而非0.5）到边裁判的三级分类比例（0.236而非0.333），到黄金分割决策阈值（0.618），系统处处体现了"宁可保守，不可冒进"的设计哲学。在交易中，避免亏损比追求盈利更重要。

2. 多维度覆盖：通过6种不同特征组合的主裁判和5种不同特征组合的边裁判，系统从趋势、价格位置、波动率、跳空等多个角度审视每个交易信号。这种多维度的交叉验证降低了单一维度误判的风险。

3. 机器学习与规则的融合：主裁判使用GMM（无监督学习），边裁判使用相似度投票（基于距离度量的监督学习变体），两者融合了不同的机器学习范式。

4. 可解释性：每个裁判使用明确命名的、具有金融意义的特征。当裁判拦截一个信号时，用户可以追溯是哪个裁判、基于什么特征做出的拦截决定。这种可解释性是"黑箱"深度学习模型所不具备的。

---

[^ump_1]: **高斯混合模型（GMM，Gaussian Mixture Model）**：一种概率模型，假设所有数据点由有限个高斯分布（正态分布）的混合生成。每个高斯分布是一个"分量"，有自己的均值（中心位置）和协方差（分布形状）。GMM通过EM算法（期望最大化）估计各分量的参数，广泛用于聚类分析。与K-Means的"硬聚类"（每个点只属于一个聚类）不同，GMM提供"软聚类"（每个点以一定概率属于多个聚类）。

[^ump_2]: **EM算法（Expectation-Maximization）**：一种迭代优化算法，用于在含有隐变量（未知量）的概率模型中估计参数。E步计算隐变量的期望（基于当前参数估计），M步最大化完全数据的对数似然（基于E步的期望）。EM算法保证每次迭代后似然函数不降，最终收敛到局部最优解。

[^ump_3]: **欧几里得距离（Euclidean Distance）**：n维空间中两点之间的直线距离，公式为d(p,q) = √(Σ(p_i - q_i)²)。在边裁判中用于衡量新交易特征向量与历史交易特征向量之间的"距离"。

[^ump_4]: **皮尔逊相关系数（Pearson Correlation Coefficient）**：衡量两个变量之间线性关系强度和方向的统计量，取值范围[-1, 1]。+1表示完全正相关，0表示无线性相关，-1表示完全负相关。在边裁判中，相关系数被用作相似度的度量——两个交易的特征向量越相似（同涨同跌），相关系数越接近1。

[^ump_5]: **StandardScaler（标准化）**：一种数据预处理方法，将特征转换为均值为0、标准差为1的分布：x' = (x - μ) / σ。标准化消除了不同特征之间因量纲（单位）不同导致的偏差，使所有特征在模型训练中具有可比的重要性。

[^ump_6]: **scipy.optimize.brute（暴力搜索/网格搜索）**：SciPy库提供的全局优化函数，在指定的参数空间内按固定步长计算每个网格点的目标函数值，返回最优参数组合。适用于参数空间维度较低（一般≤4）且目标函数非凸不可导的场景。

[^ump_7]: **EMarketTargetType**：阿布量化系统中定义的市场目标类型枚举，区分了交易数据的来源市场（A股本地/美股本地等）和目标市场。

[^ump_8]: **LazyFunc（惰性函数装饰器）**：阿布量化系统中的一个装饰器，将属性或方法的计算延迟到首次访问时。首次访问后结果被缓存，后续访问直接返回缓存值。这种模式减少了不必要的初始化开销。
