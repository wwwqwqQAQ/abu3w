# 第三章 市场数据系统

## 3.1 标的符号系统

阿布量化系统设计了一套统一的标的符号（Symbol）表示体系。Symbol类是所有市场工具的抽象表示，由三个核心字段构成：

- **market（市场类型）：** EMarketTargetType枚举，包括E_MARKET_TARGET_US（美股）、E_MARKET_TARGET_CN（A股）、E_MARKET_TARGET_HK（港股）、E_MARKET_TARGET_FUTURES_CN（中国期货）、E_MARKET_TARGET_FUTURES_GLOBAL（全球期货）和E_MARKET_TARGET_TC（加密货币）。

- **sub_market（子市场类型）：** EMarketSubType枚举，包括SH（上海）、SZ（深圳）、US_N（纳斯达克）、US_OQ（OTC）、HK（香港）、COIN（加密货币）等细分市场。

- **symbol_code（标的代码）：** 具体的交易代码，如"TSLA"、"600036"、"0001"等。

通过value惰性属性（@LazyFunc装饰器），系统将三个字段拼接为规范的字符串键，例如"usTSLA"（美股特斯拉）、"sh600036"（上交所招商银行）、"hk0001"（港交所长和）。这种设计确保了跨市场操作的统一性和可追溯性。

code_to_symbol函数实现了字符串到Symbol对象的通用解析。解析逻辑依次尝试：前缀检测（"us"→美股，"hk"→港股，"sz"→深交所，"sh"→上交所）→ 数字长度推断（6位数字→A股，5位数字→港股）→ 市场特定查询。search_to_symbol_dict函数支持模糊搜索，通过fnmatch模式匹配在公司名称、拼音和精确代码中进行查找，为用户提供了便捷的标的检索方式。

## 3.2 标的列表管理

每个市场的标的列表由专门的单例类管理。AbuSymbolCN、AbuSymbolUS、AbuSymbolHK分别管理A股、美股和港股的标的列表，这些类通过@AbuStockBaseWrap装饰器进行初始化。装饰器的初始化流程为：

1. 从CSV文件读取原始数据到DataFrame。

2. 对行业列（industry）进行因式分解（factorize），生成整数编码和名称映射序列。

3. 使用CrawlBu提供的columns_map字典将中文列名重命名为英文列名。

4. 冻结属性（通过FreezeAttrMixin），确保标的列表在系统运行期间不被意外修改。

AbuSymbolUS额外过滤了s_unusual_symbol（异常历史收益的标的），以避免引入数据偏差。各标的类提供all_symbol方法获取对应市场的全部标的，以及symbol_func方法将DataFrame行转换为标准标的代码。

期货标的由AbuFuturesCn和AbuFuturesGB管理，从futures_cn.csv和futures_gb.csv加载数据。期货标的的元数据更为丰富，包括min_deposit（最低保证金比例）、min_unit（最小交易单位，即每手数量）、commission（每手手续费）和exchange（交易所名称）。由于期货标的代码采用前缀匹配规则（例如"AU"匹配"AU0"），query_symbol方法使用了启发式的头部匹配算法。

## 3.3 K线数据模型

一根 K 线记录了股票在一个交易日里的四个关键价格：开盘价、收盘价、最高价、最低价。在程序中，一根 K 线就是一行数据，系统把它标准化成了固定的列结构：

| 列名 | 含义 | 说明 |
|------|------|------|
| open | 开盘价 | 当天第一笔成交价 |
| close | 收盘价 | 当天最后一笔成交价 |
| high | 最高价 | 当天最高成交价 |
| low | 最低价 | 当天最低成交价 |
| volume | 成交量 | 当天成交的股票数量 |
| date | 日期 | 交易日期 |
| pre_close | 前收盘价 | 上一交易日的收盘价 |
| date_week | 星期几 | 0=周一, 6=周日 |
| p_change | 涨跌幅 | 计算公式: (close - pre_close) / pre_close × 100% |

**获取单只股票的K线数据：**

make_kl_df 函数是数据获取的总入口。你要查某只股票的历史 K 线，调它就行。它内部做了四件事：

1. 通过 kline_pd 拿到原始数据（从本地缓存或网络）
2. 把日期对齐到基准指数的时间轴（不同股票上市日期不同，需要统一）
3. 去掉重复日期（停牌或数据源问题可能导致）
4. 计算 ATR 指标（14 日和 21 日平均真实波幅，用来衡量波动率）

**批量获取多只股票：**

传入一个股票列表，make_kl_df 会返回一个三维数据结构（pandas 的 Panel），三个维度分别是：股票代码、交易日期、OHLCV 字段。内部用线程池并行获取，加快速度。

**拼接历史数据：**

combine_pre_kl_pd 函数解决一个常见需求：回测期是 2 年，但计算指标可能需要往前多看 1 年。比如算 60 日均线，前 60 天还没到回测期但也需要数据。这个函数会自动查找并拼上回测期之前的额外 K 线。

## 3.4 数据缓存策略

数据缓存是量化系统效率的生命线。全市场几千只股票好几年的日线数据——每次都从网上下载，不仅慢，还会被数据源封 IP。系统的缓存策略回答两个问题："数据存哪里"和"什么时候该重新下载"。缓存支持两种后端：CSV（默认，人类可读，方便调试）和HDF5（高效，适合大规模回测）。系统的ABuDataCache模块实现了一套智能缓存管理——它会自动判断本地数据是否覆盖了用户请求的时间范围，只下载缺失的部分，避免重复下载已有的数据。

### 3.4.1 CSV缓存

CSV格式是默认的缓存方式。每个标的的每次请求生成一个独立的CSV文件，文件命名规则为{symbol}_{日期范围}.csv，存储在由g_project_data_dir/data/csv/目录下。CSV格式的优点是可读性强，便于手动检查和调试；缺点是对大型数据集而言，读写性能不如HDF5。

### 3.4.2 HDF5缓存

HDF5（Hierarchical Data Format version 5）是一种高效的二进制数据存储格式。系统通过pandas.HDFStore实现HDF5的读写。HDF5格式使用键值对结构（key=标的代码，value=DataFrame），将所有标的数据存储在一个.h5文件中。HDF5的优点是读写速度快、支持压缩、支持部分读取（无需加载全部数据）；缺点是文件格式不透明，损坏后难以修复。

### 3.4.3 智能合并策略

dump_kline_df函数实现了智能的数据合并策略。当新获取的数据与已有缓存需要合并时，函数根据数据的日期范围关系自动选择合并方式：

- 新数据完全包含缓存数据 → 替换缓存（覆盖写）。
- 新数据向左扩展（更早的日期）→ 前置拼接（新数据+旧数据）。
- 新数据向右扩展（更新的日期）→ 追加拼接（旧数据+新数据）。
- 新数据在缓存范围内 → 替换重叠部分。

这种智能合并策略避免了重复的数据下载，同时确保了缓存数据的完整性和一致性。

### 3.4.4 数据获取模式

系统通过g_data_fetch_mode全局变量控制了四种数据获取模式：

- E_DATA_FETCH_FORCE_LOCAL：强制使用本地缓存，不发起网络请求。适用于离线环境或确定性回测场景。
- E_DATA_FETCH_FORCE_ONLINE：强制从网络获取最新数据，忽略本地缓存。适用于需要最新市场数据的场景。
- E_DATA_FETCH_LOCAL_FIRST：优先使用本地缓存，仅在缓存不覆盖请求范围时才从网络获取。这是推荐的默认模式。
- E_DATA_FETCH_ONLINE_FIRST：优先从网络获取，仅在网络获取失败时回退到本地缓存。适用于网络条件良好且需要实时数据的场景。

ABuDataSource的_calc_start_end_date函数负责日期范围的协商：将缓存的日期覆盖范围与用户请求的日期范围进行比较，计算出需要从网络获取的缺失部分，实现增量的数据更新。

## 3.5 内置数据源

量化交易的第一步是拿到数据。系统对接了新浪、腾讯、百度、网易和火币等多个免费数据源，每个市场至少有一个主数据源和一个备用数据源——万一某个数据源挂了，系统可以切换到备用的。每种数据源包含一个负责发送 HTTP 请求的"市场类"和一个负责解析 JSON 响应的"解析器类"，两者通过统一的抽象基类约束接口，新增数据源只需实现这两个类即可。数据源类均继承自BaseMarket抽象基类，并通过SupportMixin混入来声明支持的市场类型。

### 3.5.1 百度股票API（BDApi）

百度股票API提供了A股的历史K线数据。该API将n_folds参数分割为约300天/段的数据块，通过分页参数start进行迭代请求，最终合并为完整数据。数据源使用了随机化的设备指纹来规避反爬虫机制。对应的BDParser手动实现了解析逻辑（而非使用@AbuDataParseWrap装饰器自动化），将JSON响应转换为标准K线DataFrame。

### 3.5.2 腾讯股票API（TXApi）

腾讯股票API支持美股（通过子市场后缀.n表示纳斯达克和.oq表示OTC进行区分）、港股和A股。该API根据n_folds参数计算需要的交易天数（n_folds * 252 + 1），一次性请求全部数据。请求URL包含了标的代码、市场编码和天数参数，响应为JSON格式。

### 3.5.3 网易股票API（NTApi）

网易股票API通过按年份拆分HTTP请求并拼接JSON响应来获取数据。这种分年请求的方式避免了单次请求数据量过大的问题，但需要处理跨年数据的拼接和去重。

### 3.5.4 新浪美股API（SNUSApi）

新浪美股API通过单次HTTP请求获取美股股票的日K线数据。响应格式为新浪特有的JavaScript变量赋值语句，需要通过正则表达式提取JSON数据部分。

### 3.5.5 新浪期货API（SNFuturesApi和SNFuturesGBApi）

SNFuturesApi处理中国期货市场的连续合约K线数据。SNFuturesGBApi处理全球期货市场数据，其响应采用JavaScript编码的JSONP格式，需要特殊的解析处理（通过ABuNetWork.parse_js函数）。

### 3.5.6 火币加密货币API（HBApi）

HBApi通过火币交易所的公开API获取BTC、LTC的日K线数据。加密货币市场为7×24小时连续交易，与股票市场的交易时段存在根本差异，系统在数据处理时对时间连续性做了特殊适配。

### 3.5.7 ABuDataParseWrap装饰器

除BDParser外，所有数据解析器均使用@AbuDataParseWrap装饰器进行标准化包装。该装饰器自动完成以下流程：接收数据源的原始JSON响应 → 提取数据数组 → 按字段名称映射到DataFrame列 → 计算pre_close（使用close.shift(1)，首行NaN用open填充）→ 计算p_change（(close - pre_close) / pre_close * 100）→ 生成date_week（使用Pandas的dayofweek）→ 返回标准化的K线DataFrame。这种装饰器模式确保了所有数据解析器输出格式的一致性，是工厂方法模式的Pythonic实现。

## 3.6 市场分类与行业分析

ABuMarket 模块提供了市场层面的通用操作。它把"这个股票属于哪个市场""怎么批量获取标的列表""怎么分割数据做并行回测"这些常用功能打包成了几个独立函数。

**标的查询与路由：**

MarketMixin 混入类通过 code_to_symbol 函数（惰性加载）从标的名称推导出市场类型和子市场类型。比如你传入 "usTSLA"，它自动识别出这是美股纳斯达克的标的。

all_symbol 函数根据市场类型，路由到对应的标的列表获取函数——美股调美股列表、A股调A股列表、港股调港股列表。不用手动判断该用哪个函数。

**并行数据分割：**

split_k_market 函数把全市场标的列表均匀切成 k 份。比如 A 股有 4000 只股票，要分 4 个进程并行分析，每个进程拿 1000 只。这是并行回测的基础设施。

choice_symbols 函数用 NumPy 的随机采样（不放回），从全市场随机抽指定数量的标的。常用于蒙特卡洛采样——不需要跑全部 4000 只，随机抽 200 只就能得到有统计意义的结果。

**训练/测试集分割：**

market_train_test_split 函数用 KFold 把数据按年份等分成训练集和测试集。n_folds 就是年份数。比如 3 年的数据，分 3 折——每年轮流当测试集，其余两年当训练集。分割结果存为 Pickle 文件，下次跑同样的实验可以直接复用，确保结果可重现。

**行业分类查询：**

ABuIndustries 模块提供行业维度的标的筛选。你输入一个行业关键词（比如"医药"），它通过模糊匹配找到对应的行业编码，然后从 AbuSymbolCN / AbuSymbolUS / AbuSymbolHK 的标的列表中筛出该行业的所有股票。

query_match_industries_symbol 函数就是这一功能的入口——给定一个关键词，返回所有匹配行业中的所有标的代码。这为行业轮动策略（在不同行业间切换配置）和行业主题投资（聚焦某个热门行业）提供了数据基础。

## 3.7 特殊市场规则

### 3.7.1 港股交易单位

港股市场的最小交易单位（每手股数）不是固定的。ABuHkUnit单例类从hk_unit.csv文件加载每只港股的标准交易单位。默认值为1000股/手。在订单执行时，下单数量必须向下取整到交易单位的整数倍。

### 3.7.2 期货交易规则

期货市场具有保证金交易和合约到期两大特征。期货数据源的零值修复（_fix_kline_pd_zero）函数专门处理期货合约到期日附近的异常价格填写（zero-price bars）。min_deposit参数控制杠杆倍数（例如，min_deposit=0.1表示10倍杠杆）。min_unit参数控制每手合约的乘数。

### 3.7.3 涨跌停限制

A股市场设有±10%的涨跌停限制（ST股票为±5%）。系统在滑点模型（SlippageBu）中通过slippage_limit_up和slippage_limit_down装饰器专门处理涨跌停情况。当检测到涨停（p_change >= 10且high == close）时，系统使用伯努利试验模拟成交概率：正常涨停的成交概率为limit_up_deal_chance（默认可配置），而集合竞价封板（high == low）的概率降至正常概率的20%。成交价格通过加权随机抽样确定——从低价到涨停价的价格序列中，使用np.linspace(0, 1, N)生成的线性递增权重进行np.random.choice抽样，使靠近涨停价的价格更容易被选为成交价。这一设计较好地模拟了涨停板排队优先级的实际市场机制。

## 3.8 数据完整性检查

ABuDataCheck模块在系统启动时验证本地数据的完整性。它检查每个市场是否有足够的CSV数据文件，对于需要全市场回测或网格搜索的场景，完整的数据是必需的。当发现数据缺失时，系统会警告用户并通过browser_down_csv_zip函数提示用户下载预设的数据集压缩包。

## 3.9 网络请求框架

ABuNetWork模块封装了统一的HTTP请求接口。采用重试机制（默认3次重试，间隔0.5秒）应对网络波动。模块内置了可选的LRU（Least Recently Used）缓存，但由于多数数据源的URL包含时间戳参数，该缓存在实际使用中通常被禁用。parse_js和ast_parse_js函数用于处理部分数据源返回的JavaScript对象格式（而非标准JSON），通过Python的ast模块进行安全的字面量解析。
