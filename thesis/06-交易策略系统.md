# 第六章 交易策略系统：FactorBuyBu与FactorSellBu

## 6.1 策略系统架构

阿布量化系统的交易策略采用因子化（Factor-based）架构，将交易决策分解为买入因子（FactorBuyBu）和卖出因子（FactorSellBu）两个独立的组件。每个因子是一个自包含的策略单元，通过组合不同的买入因子、卖出因子、选股因子和仓位管理策略，可以构建出数量庞大的复合策略。

系统的策略设计遵循"策略即对象"的面向对象范式。每个策略因子是一个Python类，继承自基类并混入方向类（做多或做空），通过实现fit_day方法定义具体的交易信号逻辑。这种设计使得策略的创建、测试和组合变得极其灵活：用户可以像搭积木一样组合不同的因子来构建策略。

根据系统文档，阿布量化系统当前应用的量化买入卖出信号策略共计18496种。这个数字来源于数百种"种子策略"通过参数变体、因子组合和市场适配衍生出的策略族。

## 6.2 买入因子基类（ABuFactorBuyBase）

买入因子基类定义了所有买入策略的统一接口和运行环境。它的核心设计包括：

### 6.2.1 方向混入类

系统通过BuyCallMixin和BuyPutMixin两个混入类实现交易方向的注入：

- BuyCallMixin：设置结果为做多（expect_direction = +1.0），价格上涨时盈利。
- BuyPutMixin：设置结果为做空（expect_direction = -1.0），价格下跌时盈利。

每个具体的买入因子必须继承其中一个且仅一个方向混入类。这种混入设计（Mixin Pattern）避免了方向逻辑在子类中的重复实现，同时保持了基类的单一职责。

### 6.2.2 执行合约

read_fit_day → fit_day是买入因子与回测引擎之间的核心合约。read_fit_day由引擎逐日调用，执行前置检查（包括skip_days冷却期检查、因子锁定检查、盘末过滤），通过后调用fit_day。子类只需实现fit_day来定义具体的交易信号逻辑。

### 6.2.3 订单生成

make_buy_order方法负责将交易信号转化为AbuOrder对象。在这一步，系统集成了三个关键处理：

1. 机器学习特征提取（AbuMlFeature）：抽取订单相关的多维度特征（趋势角度、价格百分位、波动率得分、跳空特征等），为UMP裁判系统提供输入数据。

2. UMP裁判拦截（make_ump_block_decision）：将特征向量传递给主裁判和边裁判系统，由机器学习模型判断是否应该拦截该交易信号。

3. 持仓管理：设置止损/止盈卖出因子和专属选股因子。

### 6.2.4 买入时机

系统区分了两种买入时机：

- buy_tomorrow（次日买入）：使用当日收盘数据作为信号输入，在次日开盘执行交易。这是回测的标准做法，避免了"使用当日收盘价判断信号并以当日收盘价成交"的前瞻偏差（Look-ahead Bias）。

- buy_today（当日买入）：用于T+0市场或信号不依赖当日收盘价的策略。

### 6.2.5 因子子类

系统提供了两个实用的买入因子子类：

- AbuFactorBuyTD：在基类基础上注入self.yesterday和self.bf_yesterday（前两日数据），方便实现需要昨日/前日比较的策略。

- AbuFactorBuyXD：提供self.xd_kl（最近xd天的K线切片），为基于周期的策略提供便捷的数据访问。信号发出后自动进入xd天的冷却期（skip_days），避免在同一方向上频繁重复入场。

## 6.3 核心买入策略

### 6.3.1 通道突破策略（ABuFactorBuyBreak）

通道突破是最基础的趋势跟踪策略，也是许多量化系统的起点。其信号逻辑极其简洁：

做多信号：today.close == max(close[-xd:])，即收盘价创xd日新高。

做空信号：today.close == min(close[-xd:])，即收盘价创xd日新低。

信号发出后，通过self.skip_days = self.xd进入xd天的冷却期，避免在同一方向上频繁重复入场。例如，如果xd=60（60日突破），信号发出后的60个交易日内不会再次触发同方向信号。

突破策略的底层逻辑是"牛顿第一定律在金融市场的类比"——趋势倾向于延续。当价格创出N日新高时，意味着此前的上涨动能还在持续，价格有较大概率继续上行。这个策略在趋势行情中表现出色（能够捕捉到大的趋势行情），但在震荡行情中容易产生频繁的假突破和亏损（Whipsaw效应）。

### 6.3.2 星期效应策略（ABuFactorBuyWD）

星期效应策略基于"特定星期几具有统计上显著的正/负收益率"这一市场异象。其算法分为三层筛选：

第一层——胜率筛选：使用ABuKLUtil.date_week_win计算每个工作日的历史胜率（工作日i的胜率=星期i的上涨天数/星期i的总交易天数）。保留胜率超过buy_dw阈值（默认55%）的星期几。例如，如果历史数据显示周一的胜率为58%（显著高于50%），周二为51%，则仅保留周一。

第二层——涨幅筛选：对通过第一层的工作日，计算其平均涨幅，检查是否超过两个动态阈值中的较大者：mean(|全市场日涨跌幅|) / buy_dwm和sum(|全市场日涨跌幅|) / buy_dwm，其中buy_dwm默认值为0.618（黄金分割比例）。

第三层——当天信号：在交易日当日，买入条件为三条逻辑AND：

1. 昨日下跌（p_change < 0）

2. 今日低开（today.open < yesterday.close）

3. 今日是一个被筛选出的"好日子"

买入逻辑是均值回复：在统计上有利的星期几，经历短期下跌后，价格倾向于反弹。策略的buy_date_week序列在月度任务（fit_month）中重新计算，使其能够适应市场制度的变化。这种自适应机制是策略的关键创新——传统的星期效应研究通常使用固定的历史统计，而阿布量化的实现允许窗口动态调整。

### 6.3.3 趋势回调策略（ABuFactorBuyTrend）

趋势回调策略将长期趋势跟踪与短期均值回复相结合，实现了"顺势回调买入"的经典交易理念。

AbuUpDownTrend类实现了两个核心判断：

长期趋势判断：使用AbuTLine.is_up_trend对long_kl（长度为past_factor * xd的长期K线序列）中的收盘价进行多项式拟合。如果拟合角度超过up_deg_threshold（默认3度），则判断为上升趋势。这里的趋势判断使用了TLineBu系统的高阶多项式拟合技术，而非简单的均线比较。

短期超卖判断：当价格创xd日新低（短期下跌趋势确认）且短期（长度为xd的窗口）价格的下降拟合角度小于-3度时，认为短期已经超卖。

买入信号在长期上升趋势确认且短期出现超卖时触发。这种"长期顺势、短期逆势"的策略逻辑具有坚实的行为金融学基础：在上升趋势中，短期的回调通常是情绪性的而非基本面的，趋势最终会重新确立。

AbuUpDownGolden是AbuUpDownTrend的子类，使用斐波那契黄金分割位替代简单的创新低条件。它通过ABuTLine的calc_golden函数计算价格的0.382黄金分割水平。买入发生在价格从0.382黄金分割位以下反弹至以上时。黄金分割位在上升趋势回调中是最常见的支撑位，因此这个变体策略的胜率通常高于普通的回调买入。

AbuDownUpTrend是反转版本：寻找长期下跌趋势中的标的，等待其向上突破xd日高点并建立做空头寸。

自适应双均线（Dynamic Moving Average，DM）策略是这个系统中算法复杂度最高的买入策略之一。它在经典双均线金叉策略的基础上引入了自适应机制——不是使用固定的均线周期，而是根据市场当前的波动特征动态调整快线和慢线的周期参数。

基础信号逻辑：
买入信号 = 快线上穿慢线（金叉）。当短期价格均线（快线）从下方向上突破长期价格均线（慢线）时，意味着短期趋势已经转为上涨，有较大概率带动长期趋势走强。

自适应慢线算法（_dynamic_calc_slow）：

1. 将收盘价序列按不同的窗口大小（10, 15, 20, ..., 100天，步长为5）进行重采样。

2. 对每个重采样序列计算abs(pct_change()).mean()，即该窗口大小下的平均波动率。

3. 遍历窗口大小列表，选择第一个使平均波动率超过change_threshold（默认0.12，即12%）的窗口作为慢线周期。

4. 如果没有任何窗口的波动率超过阈值，使用最大的窗口（100天）。

该算法的核心假设是：合适的均线周期应该能够捕捉到市场的主要波动周期。如果12%的平均波动率恰好出现在42天窗口，那么42日就是当前市场的"自然周期"，用42日均线作为慢线比固定的60日均线更贴合当前市场的波动特征。

自适应快线算法（_dynamic_calc_fast）：

1. 使用AbuTLine.show_least_valid_poly将大盘（benchmark）过去一个月（约22个交易日）的走势拟合为多项式曲线。

2. 所需的多项式拟合次数反映了市场的震荡程度：1次（直线）意味着趋势极度平稳；4次以上意味着震荡剧烈。

3. 根据震荡程度按比例调整快线周期：slow * 0.05（趋势平稳）到slow * 0.5（高度震荡）。

在趋势平稳的市场中，慢线周期的5%作为快线周期（例如慢线=60天，快线=3天），敏感的快速均线能捕捉到微小的趋势转变。在高度震荡的市场中，快线周期放大到慢线周期的50%（例如慢线=60天，快线=30天），以避免频繁的虚假金叉信号。

两种自适应参数都在月任务中定期重新计算，确保策略始终适应当前的市场状况。这种自适应机制是策略的关键创新，它在很大程度上解决了传统固定参数均线策略在面对不同市场状况时表现不稳定（在趋势市中参数A最优，在震荡市中参数B最优，但事先无法知道当前是什么市）的问题。

## 6.4 买入策略示例（ABuFactorBuyDemo）

该文件包含了多个示例性质的策略，展示了不同的策略设计模式：

AbuSDBreak：突破策略的震荡市场变体。在月度任务中，使用最小二乘多项式拟合评估大盘的震荡程度。如果拟合次数低于阈值（poly<2），说明市场走势简单（趋势行情），策略正常运作；否则将因子锁定（不产生交易）。这是一种简单但有效的市场环境过滤器。

AbuTwoDayBuy：两日动量策略，要求连续两日收阳且当日涨幅超过昨日。这个策略捕捉的是加速上涨的动量行情。

AbuWeekMonthBuy：定期买入策略，按周或按月定期买入。这种策略虽然简单，但作为基准策略（Baseline）非常有用，可以检验其他策略是否真的具有择时能力。

AbuBTCDayBuy：针对比特币的专门策略。比特币市场存在独特的市场微观结构（T+0、24小时交易、无涨跌停限制），该策略将基于相似股票的投票机制与BTC特有的机器学习信号相结合。

## 6.5 大盘震荡过滤器（ABuBuyFactorWrap）

ABuLeastPolyWrap是一个类装饰器，为任意买入因子添加大盘震荡过滤功能。装饰器通过拦截_init_self、fit_day和fit_month方法，透明地添加了基于大盘多项式拟合的市场环境判断逻辑。

其核心算法与AbuSDBreak相同：对大盘（benchmark指数）的价格序列进行多项式拟合，如果最优拟合次数低于阈值，说明市场走势简单（趋势性行情），因子正常运行；否则锁定因子（不产生交易信号）。

使用装饰器而非继承来实现这一功能是一个精妙的设计选择——任何买入因子（无论是系统内置的还是用户自定义的）都可以通过简单地添加@AbuLeastPolyWrap装饰器来获得大盘震荡过滤能力，无需修改因子本身的代码。这体现了面向切面编程（AOP）的思想。

## 6.6 卖出因子体系

卖出因子体系与买入因子镜像对称，但有三个关键区别：


- 卖出因子处理多个订单。每个买入因子可能产生多个未平仓订单，卖出因子需要逐个检查这些订单是否满足出场条件。这与买入因子（每个交易日最多产生一个信号）的1对1逻辑不同。


- 卖出因子声明支持的方向。通过ESupportDirection枚举（DIRECTION_CALL和DIRECTION_PUT），卖出因子可以声明自己支持做多方向、做空方向或两者都支持。


- 卖出因子的fit_day方法需要接收当前的订单对象作为参数，决定该特定订单是否应该被平仓。

read_fit_day方法在接收到当日的所有未平仓订单后，首先按support_direction过滤（仅保留在因子支持方向范围内的订单），然后对每个订单调用fit_day。这一设计使得同一个卖出因子可以处理来自不同买入因子的订单。

### 6.6.2 ATR日内止损（ABuFactorPreAtrNStop）

这是最硬性的止损规则——防范单日极端亏损：

```
if (today.pre_close - today.close) * order.expect_direction > today.atr21 * pre_atr_n:
    触发卖出
```

数学解释：(pre_close - close)是单日的价格变动（开盘跳空+日内波动）。乘以order.expect_direction（做多订单为+1，做空订单为-1）进行方向标准化后，正值表示不利变动。当这个不利变动超过ATR21的pre_atr_n倍（默认1.5倍）时，触发止损。

pre_atr_n=1.5意味着如果单日的不利波动超过最近21天平均真实波幅的1.5倍，就无条件离场。这个阈值在统计上大约对应日收益率分布的负1.5到负2个标准差——发生概率约为5-7%——确实属于"异常不利"的情况。

该因子支持当日卖出（sell_today），因为止损的紧迫性不允许再等一个交易日。

止盈条件：profit > 0 且 profit > stop_win_n * stop_base

止损条件：profit < 0 且 profit < -stop_loss_n * stop_base

stop_base是21日和14日ATR的和，代表了价格的"正常波动范围"。如果盈利超过这个范围的n倍，止盈（获利了结）；如果亏损超过这个范围的n倍，止损（截断亏损）。

使用两个周期的ATR之和（而非单个ATR）作为基准，可以在一定程度上平滑单一ATR的噪声。

### 6.6.4 追踪止盈（ABuFactorCloseAtrNStop）

追踪止盈（Trailing Stop）从持仓期间的最高（最低）点计算回撤：

```
max_close = 从买入日到今日的最高收盘价（做多）

回撤 = (max_close - today.close) * order.expect_direction
```

(公式6-2)

触发条件：
1. 已有足够的未实现利润：(max_close - buy_price) * direction > atr21（至少1倍ATR）

2. 从峰值的回撤过大：回撤 > atr21 * close_atr_n（默认3倍ATR）

追踪止盈的优点在于它"让利润奔跑"（Let profits run）——在没有出现显著回撤前，不会因为固定的止盈目标而过早离场。同时，当趋势出现实质性反转时，又能及时保护已有的利润。

### 6.6.5 突破卖出（ABuFactorSellBreak）

突破卖出的信号逻辑与突破买入完全对称：today.close == min(close[-xd:])，即收盘价创xd日新低。这意味着短期趋势已经确认转为下跌，在趋势跟踪策略中应该离场。

### 6.6.6 时间止损（ABuFactorSellNDay）

时间止损（Time Stop）是最简单的卖出规则：持有N天后强制卖出，无论盈亏。其设计理念是：如果一个交易信号在N天后仍未产生预期的行情，那么这个信号很可能是错误的，应该了结离场。

系统对每个未平仓订单维护一个keep_days计数器，每日递增。当keep_days >= sell_n时触发卖出。

### 6.6.7 双均线卖出（ABuFactorSellDM）

双均线卖出是ABuFactorBuyDM的反向镜像。对于做多订单，快线下穿慢线（死叉）时卖出；对于做空订单，快线上穿慢线（金叉）时卖出。

## 6.7 策略组合

阿布量化系统的一个核心设计理念是策略组合的灵活性。每个买入因子可以配置：

1. 一个或多个专属的卖出因子（attached_sell_factors）：这些卖出因子仅对该买入因子产生的订单生效。例如，通道突破买入（ABuFactorBuyBreak）可以搭配追踪止盈卖出（ABuFactorCloseAtrNStop），而趋势回调买入（ABuUpDownTrend）可以搭配时间止损（ABuFactorSellNDay）。

2. 一个或多个专属的选股因子（stock_pickers）：这些选股因子仅在该买入因子被激活时运行。例如，趋势回调策略可能配置一个"低波动率选股"因子，仅选择波动适中的标的进行回调买入。

3. 全局卖出因子：对所有买入因子产生的订单都生效的卖出规则。例如ATR日内止损（ABuFactorPreAtrNStop）通常是全局的——无论哪个买入因子产生的订单，都应该防范单日极端亏损。

通过这种分层组合机制，系统可以从数百个"原子策略"（基础因子）中组合出数千个"分子策略"（因子组合），再从分子策略的参数变体和市场适配中衍生出数万个"策略族"。这就是"数百种种子策略衍生出18496种策略"的实现机制。
