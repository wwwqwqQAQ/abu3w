# 第十章 机器学习模块与AI集成：MLBu与ClaudeBu

## 10.1 MLBu：通用机器学习模块

MLBu是阿布量化系统中独立于UMP裁判系统的通用机器学习模块。如果说UMP是"专用ML"（为交易信号过滤这一特定任务优化），那么MLBu就是"通用ML"——封装了scikit-learn生态中常用的分类、回归、聚类和降维算法，为量化交易领域的各种ML应用场景提供统一接口。

### 10.1.1 模型工厂（ABuMLCreater）

ABuMLCreater作为模型工厂，集中管理所有支持的机器学习模型的实例化。支持的模型包括：
- 监督学习（分类）：SVC（支持向量机）
- DecisionTreeClassifier（决策树）
- RandomForestClassifier（随机森林）
- AdaBoostClassifier
- BaggingClassifier
- GradientBoostingClassifier
- KNeighborsClassifier（KNN）
- LogisticRegression（逻辑回归）。

监督学习（回归）：LinearRegression（线性回归）、PolynomialRegression（多项式回归）。

无监督学习：PCA（主成分分析）、KMeans（K均值聚类）、GaussianMixture（高斯混合模型）。

序列模型：HMM（隐马尔可夫模型[^ml_4]，通过hmmlearn库）。

每个模型都有对应的_best()变体方法，使用_estimators_prarms_best()函数自动搜索最优超参数。搜索方式有二：如果用户提供了param_grid（参数网格），使用GridSearchCV进行交叉验证网格搜索；否则调用模型特定的默认搜索回调（如random_forest的n_estimators搜索）。

模型导入采用了回退链（Fallback Chain）设计：优先尝试导入xgboost.sklearn（XGBoost[^ml_1]的sklearn兼容接口），如果失败则回退到sklearn的GradientBoostingClassifier；优先尝试导入hmmlearn（更专业的HMM库），如果失败则回退到sklearn的GaussianMixture。这种回退设计确保了系统在不同依赖环境下都能正常运行。

### 10.1.2 核心ML包装器（ABuML）

ABuML是模块的核心类，组合了特征矩阵x、标签向量y、关联的DataFrame df和一个ABuMLCreater模型工厂。它的设计目标是简化"从数据到模型评估"的完整流程。

学习类型自动检测（EMLFitType.AUTO）：系统通过检查标签向量中唯一值的数量来自动判断任务是分类还是回归。如果len(np.unique(y)) <= 10，判定为分类任务（标签是离散的类别）；否则判定为回归任务（标签是连续的值）。10这个阈值是一个实用的经验值——实际交易数据中的分类（如盈利/亏损的二分类，或大赚/小赚/平/小亏/大亏的多分类）通常不超过10个类别。

entry_wrapper装饰器标准化了模型训练和评估的入口流程：自动检测学习类型 → 验证模型是否支持该学习类型 → 设置相应的评估方法。

### 10.1.3 非均衡概率准确率评分

**源码片段：非均衡概率准确率评分**

```python
    """
    类装饰器函数，对关键字参数中的fiter_type进行标准化，eg，fiter_type参数是'clf'， 转换为EMLFitType(fiter_type)
    赋予self.fiter_type，检测当前使用的具体学习器不在support参数中不执行被装饰的func函数了，打个log返回

    :param support: 默认 support=(EMLFitType.E_FIT_CLF, EMLFitType.E_FIT_REG, EMLFitType.E_FIT_HMM,
                           EMLFitType.E_FIT_PCA, EMLFitType.E_FIT_KMEAN)
                    即支持所有，被装饰的函数根据自身特性选择装饰参数
    """

    def decorate(func):
        @functools.wraps(func)
        def wrapper(self, *args, **kwargs):
            org_fiter_type = self.fiter_type
            if 'fiter_type' in kwargs:
                # 如果传递了fiter_type参数，pop出来
                fiter_type = kwargs.pop('fiter_type')
                # 如果传递的fiter_type参数是str，eg：'clf'， 转换为EMLFitType(fiter_type)
                if isinstance(fiter_type, six.string_types):
                    fiter_type = EMLFitType(fiter_type)
                self.fiter_type = fiter_type

            check_support = self.fiter_type
            if self.fiter_type == EMLFitType.E_FIT_AUTO:
                # 把auto的归到具体的分类或者回归
                check_y = self.y
                if 'y' in kwargs:
                    check_y = kwargs['y']
                check_support = EMLFitType.E_FIT_CLF if len(np.unique(check_y)) <= 10 else EMLFitType.E_FIT_REG
            if check_support not in support:
                # 当前使用的具体学习器不在support参数中不执行被装饰的func函数了，打个log返回
                self.log_func('{} not support {}!'.format(func.__name__, check_support.value))
                # 如果没能成功执行把类型再切换回来
                self.fiter_type = org_fiter_type
                return

            return func(self, *args, **kwargs)

        return wrapper

```


cross_val_prob_accuracy_score是MLBu中最具交易特色的评估方法。它不采用传统的准确率（accuracy = 正确预测数/总预测数），而是引入了"概率阈值"和"弃权"机制：

1. 使用KFold交叉验证，对每个fold调用模型的predict_proba方法获取预测概率。

2. 使用给定的阈值（threshold）将概率二值化：概率≥阈值的预测为"有效预测"，否则为"弃权"。

3. 对"有效预测"计算四个指标：

   - accuracy：有效预测中的正确率
   - effect_cnt：有效预测的数量
   - effect_rate：effect_cnt / 总交易数（覆盖率）
   - score：effect_rate * accuracy（综合得分）

这个框架的独特之处在于它显式地允许模型"弃权"——对于置信度不足的预测，不做出判断。在交易场景中，"不确定就不交易"比"强行预测然后亏损"要好得多。

阈值搜索方法提供了两个方向的搜索策略：
- search_match_neg_threshold：从低阈值向高阈值搜索（0.01→0.50），适用于"确保最低准确率"的场景。低阈值意味着更多的预测会被接受（高覆盖率），但需要筛选出其中准确率达到要求的部分。
- search_match_pos_threshold：从高阈值向低阈值搜索（0.50→0.99），适用于"仅接受高置信度预测"的场景。高阈值意味着只有模型非常有把握的预测才会被接受。

### 10.1.4 测试数据工厂

系统内置了两个示例数据集用于快速验证ML流程：

create_test_fiter：使用sklearn内置的鸢尾花（Iris）数据集，150个样本，4个特征，3个类别。用于快速的功能测试。

create_test_more_fiter：使用泰坦尼克号（Titanic）数据集，并展示了完整的特征工程流水线：

1. 使用RandomForestRegressor对缺失的Age值进行填补（用其他特征预测年龄）

2. 对Cabin（客舱号）进行二值化（有/无）

3. 对分类变量（Cabin、Embarked、Sex、Pclass）进行独热编码（One-Hot Encoding）

4. 对Age和Fare进行StandardScaler标准化

这个特征工程流水线是一个完整的ML预处理模板，用户可以直接套用到自己的交易数据上。

### 10.1.5 可视化分析（ABuMLExecute）

MLBu提供了丰富的可视化分析工具：
- plot_learning_curve：学习曲线（训练集大小对模型性能的影响）
- graphviz_tree：决策树的可视化（导出为Graphviz DOT格式→PNG图片）
- plot_decision_boundary：二维特征平面的决策边界可视化

### 10.1.6 超参数优化（ABuMLGrid）

ABuMLGrid封装了GridSearchCV的常用模式：
- grid_search_init_kwargs：单参数搜索，结果以"参数值-vs-得分"折线图展示
- grid_search_mul_init_kwargs：多参数搜索，结果以散点图展示
- 专用的搜索回调：n_estimators、max_depth、n_neighbors、n_components的自动搜索

评分函数自动选择：分类任务使用accuracy（准确率），回归任务使用explained_variance_score（解释方差得分）。

### 10.1.7 业务逻辑层（ABuMLPd）

ABuMLPd通过__getattr__委托将所有ABuML的方法暴露出来，同时附加交易业务相关的逻辑。

ClosePredict示例展示了回归预测：使用特斯拉（TSLA）股票的开盘价、最高价、最低价、前收盘价和星期几作为特征，预测当日收盘价。这是一个经典的"利用已知信息预测未知信息"的监督学习设置——在交易日开始时，开盘价、最高价和最低价都是已知的（使用盘中的数据），只有收盘价是未知的。

BtcBigWaveClf示例展示了分类预测：判断比特币交易日是否为"大波动日"（涨跌幅超过5.5%）。最有趣的是其"兄弟组"（Sibling Group）特征构建方法——将每3个连续交易日打包为一个特征向量，第一个交易日加前缀one_，第二个加前缀two_，第三个加前缀today_。第三个交易日的big_wave标签作为y（预测目标）。这种"用前两天特征预测第三天"的设计避免了使用未来信息（前向偏差[^ml_6]）。

## 10.2 ClaudeBu：AI大语言模型集成

ClaudeBu是阿布量化系统中最具前瞻性的模块——它将Anthropic的Claude大语言模型集成到量化交易工作流中。虽然该模块的文件结构相对简洁（约400行Python代码），但其设计思想代表了量化交易与生成式AI融合的一个重要探索方向。

### 10.2.1 API配置（ClaudeConfig）

系统支持三种Claude模型，按不同的成本-能力层级配置：

- MODEL_FAST = "claude-haiku-4-5-20251001"：快速且经济，用于批量交易裁判
- MODEL_STANDARD = "claude-sonnet-4-6"：默认模型，平衡速度和质量
- MODEL_SMART = "claude-opus-4-8"：最强推理能力，用于策略分析

配置类提供了两个场景化的配置方法：
- for_judge_fast()：切换到haiku模型、1024 tokens输出、temperature=0.1。低temperature确保裁判决策的一致性（同样的输入给出同样的判断）。
- for_strategy()：切换到opus模型、8192 tokens输出、temperature=0.2。更大的输出空间允许生成详细的策略分析报告。

API Key从环境变量ANTHROPIC_API_KEY读取，或通过构造函数参数传入。

### 10.2.2 Claude裁判（ClaudeJudge）

ClaudeJudge是实现"AI替代传统ML裁判"的核心类。它支持两种工作模式：

**规则模式（"rule" mode）：**

这是默认的工作模式，核心思路是让Claude从历史交易数据中总结出拦截规则，然后本地执行拦截。

规则提取（_extract_rules）的工作流程：

1. 从历史交易中采样最多80条（所有亏损交易+部分盈利交易，确保两类样本都在规则提取的上下文中）。80条的限制来自API的上下文窗口约束——交易记录以结构化的文本格式呈现，每条包含16+个特征值的描述。

2. 将采样数据和RULE_EXTRACTION_PROMPT发送给Claude。Prompt要求Claude分析特征模式，生成一个Python函数judge_trade(features) → bool（True=拦截，False=放行）。

3. 从Claude的回复中提取markdown代码块（python...）。

4. 使用exec()动态编译和执行提取出的Python代码，将judge_trade函数绑定到self._rule_func。

5. 如果上述任何步骤失败（无API Key、API调用失败、代码编译失败），回退到_set_default_rules()的硬编码默认规则。

默认回退规则是一套计分系统：
- 价格处于85%百分位以上 AND 短期角度<3度：+3分（追高买入检测）
- 长期角度<-5度：+2分（下跌趋势中买入检测）
- ATR标准差>0.8 AND 价格处于90%百分位以上：+3分（高波动追高检测）
- 存在10日内的向下跳空且力量<-2：+3分（跳空下跌后买入检测）

累计≥5分时拦截交易。这套默认规则是高度保守的——它主要拦截的是"追高"和"逆势"类交易行为。

规则模式的最大优势是离线可用：规则提取是"一次性"的API调用，提取完成后规则在本地执行（不依赖网络和API），响应时间在毫秒级。

**直接模式（"direct" mode）：**

在直接模式下，每个交易信号实时发送给Claude进行判断：

1. 将交易信号的特征按类别分组（趋势角度组、价格位置组、波动率组、跳空组），以结构化的文本格式呈现。

2. 发送DIRECT_JUDGE_PROMPT给Claude，要求返回JSON格式的{"approve": bool, "confidence": float, "reason": str}。

3. 解析JSON响应，根据approve字段决定拦截或放行。

直接模式引入了两个优化：

特征缓存：对特征值取3位小数的MD5哈希作为缓存键。完全相同的特征向量不需要重复调用API——这在买入信号特征值经常重复的场景下能节省大量API成本。_warm_cache()方法用训练数据的前20条交易预填充缓存。

批量裁判（_judge_batch）：将多个交易信号合并为一个API调用，减少HTTP往返次数。使用BATCH_JUDGE_PROMPT要求Claude返回数组格式的JSON。

### 10.2.3 Claude策略分析师（ClaudeStrategist）

ClaudeStrategist实现的是回测后（Post-hoc）的策略分析——它不是裁判信号，而是分析策略在回测中的整体表现。

analyze()方法提供完整策略报告：

1. 从回测的orders_pd和capital_pd中计算关键指标：胜率、总利润、平均利润、总收益率、最大回撤、夏普比率（年化，sqrt(252)）。

2. 分层抽样：从所有交易中抽取最多50条（一半最差+一半最好），发送给Claude进行深度分析。

3. Claude从五个维度输出分析：总体概况（summary）、亏损模式（loss_patterns）、盈利模式（win_patterns）、参数建议（parameter_suggestions）、下一步行动（next_steps）。

quick_scan(top_n=10)方法提供快速诊断：对最好的10笔和最差的10笔交易，让Claude用一句话总结每笔交易的成败关键因素。

suggest_parameters()方法提供参数优化建议：传入买入因子和卖出因子的当前配置和策略表现指标，让Claude基于其对金融市场的理解提出参数调整方向。

所有ClaudeStrategist的分析请求都复用了ClaudeJudge的_call_claude()方法，确保了API调用的统一管理和错误处理。

### 10.2.4 UMP兼容层

ClaudeJudge实现了与UMP裁判系统完全兼容的接口：
- class_unique_id()返回'claude_judge'
- is_buy_ump()返回True（买入裁判）/ ClaudeSellJudge返回False（卖出裁判）
- predict(**ml_feature_dict)返回-1（拦截）或0（放行）

由于实现了与UMP系统相同的接口（class_unique_id + predict），ClaudeJudge可以无缝地作为"用户自定义裁判"（通过ABuUmpManager.append_user_ump()）插入到现有的UMP裁判体系中。这意味着Claude裁判可以与GMM主裁判和相似度边裁判并联运行，形成"机器学习裁判+AI裁判"的双重验证。

---

[^ml_1]: **XGBoost（eXtreme Gradient Boosting）**：一种基于梯度提升决策树（GBDT）的机器学习算法，由陈天奇于2014年开发。通过二阶泰勒展开近似损失函数、正则化项防止过拟合、列采样和并行化等技术，在结构化/表格数据的分类和回归任务中表现出色。

[^ml_2]: **GridSearchCV（交叉验证网格搜索）**：scikit-learn提供的超参数优化方法。对参数网格中的每个组合，使用交叉验证评估模型性能，选择平均得分最高的组合。CV（Cross-Validation）确保评估的稳定性。

[^ml_3]: **独热编码（One-Hot Encoding）**：将分类变量转换为机器学习模型可以处理的数值格式。对于一个有k个类别的变量，创建一个k维向量，其中只有一个维度为1（表示该类别），其余为0。

[^ml_4]: **隐马尔可夫模型（HMM）**：一种统计模型，假设系统在不可观测的（"隐藏的"）状态之间转换，每个状态以一定概率产生可观测的输出。在金融领域，HMM常用于将市场状态（趋势/震荡/反转）建模为隐藏状态。

[^ml_5]: **ROC曲线与AUC**：ROC（Receiver Operating Characteristic）曲线以假阳性率（FPR）为x轴、真阳性率（TPR）为y轴，展示分类器在不同阈值下的表现。AUC（Area Under the Curve）是ROC曲线下的面积，AUC=1表示完美分类器，AUC=0.5等同于随机猜测。

[^ml_6]: **前向偏差（Look-ahead Bias）**：在回测中使用"未来信息"来做出"过去"的交易决策，导致回测结果虚高。例如在t日收盘时使用t日的收盘价来决定t日的交易是一种前向偏差——因为在现实中，你无法在收盘前精确知道收盘价。

[^ml_7]: **MD5哈希**：一种广泛使用的加密哈希函数，将任意长度的数据映射为128位（16字节）的哈希值。在ClaudeJudge中用于特征缓存——相同的特征值产生相同的MD5哈希，可以快速判断两个特征向量是否完全一致。
