# 第十一章 回测[^bt_3]引擎与性能度量：TradeBu与MetricsBu

## 11.1 回测引擎架构

回测引擎（Backtesting Engine）是量化交易系统的核心组件，负责在历史数据上模拟策略的执行过程。阿布量化系统的回测引擎由TradeBu模块实现，采用"订单→操作→资金演化"的三阶段管道架构。

## 11.2 基准时间轴（ABuBenchmark）

AbuBenchmark定义了回测的时间框架。它获取一个市场基准指数（美股用纳斯达克指数IXIC，A股用上证指数000001，港股用恒生指数HSI，期货用AU0（沪金连续），加密货币用BTC）的K线数据。所有交易标的的K线数据通过reindex操作对齐到这个基准的时间轴上——不同的标的可能有不同的上市日期、停牌日期和交易日，通过对齐确保所有时序操作的一致性。

基准指数的时间跨度（由n_folds、start和end参数共同决定）定义了回测的时间范围。如果start='2018-01-01'、end='2019-12-31'、n_folds=2，则基准K线覆盖2018年1月1日至2019年12月31日（约504个交易日）的数据。

## 11.3 资金账户模拟（ABuCapital）

ABuCapital是回测引擎中最复杂的类，它维护了一个模拟的资金账户，随时间演化。其核心数据结构是capital_pd（一个按基准日期索引的DataFrame），包含以下列：

- cash_blance：每日的可用现金余额。使用NaN填充并向前填充（ffill），因为现金在无交易的日期保持不变。

- stocks_blance：每日的持仓股票总市值。等于所有标的的*_worth列之和（每个标的有一列call_worth和put_worth，分别记录做多和做空持仓的市值）。

- capital_blance：每日的总资产 = cash_blance + stocks_blance。

- 每个持有标的有多列：{symbol}_call_keep（做多持仓数量）、{symbol}_call_worth（做多持仓市值）、{symbol}_put_keep（做空持仓数量）、{symbol}_put_worth（做空持仓市值）。

关键交易操作：

buy_stock(order)：检查现金是否足够支付买入成本和佣金 → 增加持仓数量 → 减少现金。使用commission.buy_commission_func上下文管理器计算佣金。

sell_stock(order)：计算卖出收入。对于做空订单（expect_direction=-1），卖出收入的公式为sell_earn_price = (sell_price - buy_price) * (-1) + buy_price，将做空的"卖高买低"利润转换为正数。减少持仓数量 → 增加现金。

apply_k_line(kl_pd, buy_type_head)：在每个交易日结束时，根据当日收盘价重新计算所有持仓的市值：worth = close_price * quantity。这是"逐日盯市[^bt_1]"（Mark-to-Market）的过程。

## 11.4 订单系统（AbuOrder）

AbuOrder使用__slots__机制声明属性，而非使用__dict__字典。这是因为回测过程可能产生数百万个订单对象（全市场回测 × 多策略组合 × 多年数据），使用__slots__可以大幅减少每个订单对象的内存占用（从~1KB降至~80字节），同时提高属性访问速度。

关键字段包括：
- buy_symbol：交易标的
- buy_date：买入日期
- buy_price：买入价格（经滑点调整后）
- buy_cnt：买入数量（经仓位管理和交易单位取整后）
- buy_factor：触发该订单的买入因子名称
- buy_pos：仓位比例
- expect_direction：期望方向（+1.0做多，-1.0做空）
- sell_type：卖出类型（'win'=盈利卖出，'loss'=亏损卖出，'keep'=持仓中）
- sell_price：卖出价格
- ml_features：ML特征字典，由AbuMlFeature提取

fit_buy_order(day_ind, factor_object)方法是订单生成的核心：

1. 调用滑点类的fit_price()获取买入价格

2. 调用仓位管理类的fit_position()获取买入数量

3. 按该市场的最小交易单位向下取整数量

fit_sell_order(day_ind, factor_object)方法处理卖出：

1. 调用卖出滑点的fit_price()获取卖出价格

2. 根据期望方向和实际盈亏判断卖出类型（盈利/亏损）

ABuTradeExecute实现了从订单到操作再到资金模拟的完整管道。

第一步：calc_simple_profit计算每笔订单的简化利润（不计佣金）：
```
profit = (sell_price - buy_price) * buy_cnt * expect_direction
```

(公式11-1)

第二步：make_orders_pd将订单列表转换为DataFrame，添加profit_cg（利润率）= profit / (buy_price * buy_cnt)和result（结果码：1=盈利、-1=亏损、0=未平仓），并通过AbuMlFeature.unzip_ml_feature展开ML特征字典为多列。

第三步：transform_action将按时间排序的orders_pd转换为买入操作和卖出操作的交替序列（action_pd）。这一步的关键挑战是：订单在orders_pd中是按"卖出日期"排序的（因为卖出后才构成一条完整的订单记录），而操作序列需要按"买入日期"排序来模拟时间推进。

第四步：apply_action_to_capital是核心模拟循环。对于action_pd中的每一行（每个操作）：

1. 如果操作为买入：调用capital.buy_stock()

2. 如果操作为卖出：调用capital.sell_stock()

3. 记录操作是否实际成交（deal列）——资金不足或持仓不足可能导致操作失败

模拟循环完成后，调用capital.apply_k_line计算逐日市值变化。

## 11.6 K线数据管理（ABuKLManager）

ABuKLManager是在回测会话中管理K线数据的中央缓存。它维护两个层级的缓存：

- pick_time缓存：按标的代码索引的回测期K线数据字典
- pick_stock缓存：嵌套字典{symbol: {xd: DataFrame}}，按标的代码和回看天数双键索引

这种双层缓存设计避免了在选股阶段（需要不同xd的K线数据）和择时阶段（需要回测期的K线数据）之间重复获取相同的数据。

batch_get_pick_time_kl_pd方法实现了批量并行K线数据获取，通过add_process_env_sig装饰器确保子进程继承正确的环境配置。

## 11.7 性能度量体系

MetricsBu模块提供了全面的回测绩效评估。

ABuMetricsBase是核心度量类，计算两大类指标：

### 11.7.1 资金曲线指标

系统使用empyrical库（Quantopian开源的金融性能分析库）计算时间序列指标：

algorithm_returns（策略日收益率）：
```
returns = caπtal_blance.pct_change() * stocks_full_rate_factor
```

(公式11-2)
stocks_full_rate_factor是一个调整因子，处理因仓位取整导致的"剩余现金"问题——让收益率计算更准确地反映策略的实际投资回报。

algorithm_cum_returns（策略累计收益率）：cum_returns(algorithm_returns)，即收益率的连乘。

年化收益率：
```
annualized = (trade_year / num_trading_days) * period_returns
```

(公式11-3)
其中trade_year是回测覆盖的自然年数，num_trading_days是实际交易天数。

年化波动率（Annual Volatility）：annual_volatility(returns)，即日收益率的标准差乘以√252。

夏普比率（Sharpe Ratio）：
```
Sharpe = (R_p - R_f) / σ_p
```

(公式11-4)
其中R_p为策略年化收益率，R_f为无风险利率（系统默认设为0），σ_p为年化波动率。夏普比率衡量每单位风险带来的超额回报。

信息比率（Information Ratio）：
```
IR = (R_p - R_b) / σ(R_p - R_b)
```

(公式11-5)
衡量策略相对于基准的超额收益的稳定性。

Alpha和Beta：通过alpha_beta_aligned函数计算。Beta衡量策略收益对基准收益的敏感性（Beta=1表示策略与市场同步波动），Alpha衡量扣除市场波动影响后的超额收益。

最大回撤（Max Drawdown）：
```
MDD = max[(峰值 - 谷值) / 峰值]
```

(公式11-6)
衡量策略从资金曲线最高点到最低点的最大相对跌幅，是评估策略风险的直观指标。

### 11.7.2 交易统计指标

每笔交易的利润率：
```
profit_cg = profit / (buy_price * buy_cnt)
```

(公式11-7)

胜率（Win Rate）：
```
win_rate = 盈利交易数 / 总已平仓交易数
```

(公式11-8)

平均盈利（Gains Mean）：所有盈利交易的profit_cg均值。

平均亏损（Losses Mean）：所有亏损交易的profit_cg均值。

盈亏比（Win/Loss Profit Rate）：
```
win_loss_ratio = -Σ(盈利总和) / Σ(亏损总和)
```

(公式11-9)

平均持仓天数（keep_days_mean）：所有已平仓交易的平均持有天数。

总利润（all_profit）：所有交易利润的总和。

买入成交率（buy_deal_rate）：实际执行的买入操作数 / 尝试的买入操作数。低于100%说明存在资金不足导致的买入失败。

## 11.8 交叉验证（ABuCrossVal）

ABuCrossVal实现了基于相关性的交叉验证，用于评估策略在不同市场环境下的稳健性：

1. 计算全市场所有标的与基准指数的日收益率相关系数（使用皮尔逊相关系数）。

2. 使用pd.qcut(corr_series, cv)将标的按照与基准的相关性等分为cv组（分位数[^bt_7]分组）。

3. 从每组中随机抽取标的组成测试集，在cv个进程中并行运行回测。

4. 聚合各组的绩效指标，计算加权平均（权重为各组的交易数量）。

这种交叉验证方法的经济学含义是：策略在不同"市场Beta"的标的子集上的表现是否一致。如果策略在高相关性的标的上表现良好，在低相关性的标的上表现较差，说明策略本质上是在"交易Beta"而非"交易Alpha"——这是一种需要警惕的偏差。

## 11.9 网格搜索参数优化（ABuGridSearch）

ABuGridSearch实现了策略参数的自动化搜索和优化，其设计模拟了scikit-learn的GridSearchCV的哲学：

ParameterGrid.product方法生成所有参数组合的笛卡尔积。例如，xd=[20, 30, 60]，class=[FactorA, FactorB]生成6种不同的因子配置。

combine_same_factor_class方法处理"同名因子、不同参数"的情况——将多个同类型的因子实例折叠为参数列表，进行组合优化。

grid_search类方法提供简单的策略级网格搜索：生成所有买入因子×卖出因子×选股因子的组合，串行或并行运行回测，返回按绩效指标排名后的结果。

fit()实例方法对每个因子组合启动一个子进程运行独立回测。关键设计是：在并行化网格搜索中，每个子进程内部的回测使用单进程（n_process_pick_time=1和n_process_kl=1），因为外层已经是并行化（由网格搜索的n_jobs控制），内层并行（"并行中套并行"）会导致CPU过载。

### 11.9.1 评分系统（ABuMetricsScore）

AbuBaseScorer提供了对网格搜索结果进行标准化评分的框架：

1. 对每个因子组合的回测结果计算多个度量指标

2. 从每个度量指标中提取标量得分

3. 使用基于排名（rank-based）的线性缩放将各指标归一化到[0, 1]区间

4. 计算加权综合得分（score）

WrsmScorer（Weighted Rank Score Model Scorer）是具体的评分实现，默认使用四个等权重的指标：win_rate、returns、sharpe和max_drawdown。用户可以通过调整权重来偏重不同的指标（例如，对保守型策略增加max_drawdown的权重）。

基于排名的归一化而非基于原始值的归一化，是评分系统的一个细致设计。原始值归一化（min-max或z-score）容易受到极端值的影响——一个异常高的收益率可能将所有其他组合的得分压缩到接近于0。排名归一化则更稳健——排名第一的组合得分总是1.0，排名最后的组合得分总是0.0，中间的均匀分布。

## 11.10 交易可视化

ABuTradeDrawer提供了交易结果的可视化：
- plot_his_trade：在价格K线图上标注买入点和卖出点，用颜色区分盈利交易和亏损交易
- plot_capital_info：绘制资金曲线的三个面板——总资产曲线、持仓市值曲线和分布直方图

ABuTradeProxy提供了订单集合的集合操作，支持对不同策略的订单结果进行对比分析：
- union_in_2orders（|）：合并两个策略的订单
- intersection_in_2orders（&）：取两个策略的共同订单
- difference_in_2orders（-）：一个策略有而另一个策略没有的订单

[^bt_1]: **逐日盯市（Mark-to-Market）**：在每个交易日结束时，按当日收盘价重新计算所有持仓的市值，反映未实现盈亏的变化。这是基金净值和期货保证金计算的标准方法。

[^bt_2]: **滑点（Slippage）**：交易执行价格与信号触发时理论价格之间的差异。产生原因包括买卖价差、市场深度不足（大额订单的价格冲击）和执行延迟。

[^bt_3]: **回测（Backtesting）**：在历史市场数据上模拟交易策略的执行过程，评估策略在过去的表现。回测是策略开发的核心环节，但存在过拟合风险——策略可能在历史数据上表现优异，但在未来数据上失效。

[^bt_4]: **__slots__**：Python类的特殊属性，显式声明实例可拥有的属性名称列表。使用__slots__的类不再为每个实例创建__dict__字典，可减少内存占用（通常减少50-80%）并提高属性访问速度。代价是不能动态添加新属性。

[^bt_5]: **笛卡尔积（Cartesian Product）**：从多个集合中各取一个元素的所有可能组合。例如，集合A={a,b}和集合B={1,2,3}的笛卡尔积为{(a,1),(a,2),(a,3),(b,1),(b,2),(b,3)}，共2×3=6种组合。

[^bt_6]: **empyrical**：Quantopian公司开源的Python金融性能分析库，提供了累计收益率、年化波动率、夏普比率、最大回撤、Alpha和Beta等金融指标的计算函数。

[^bt_7]: **分位数（Quantile）**：将排序后的数据等分为若干组的分割点。qcut(data, 5)将数据分为5个等大小的组（五分位数），每组约占总数据的20%。
