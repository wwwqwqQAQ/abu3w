# 第八章 仓位管理与风险控制：BetaBu与SlippageBu

## 8.1 仓位管理的理论框架

仓位管理（Position Sizing）是决定每笔交易买卖多少数量（股/手/合约）的系统。它回答的是一个看似简单但实则深刻的问题："这次应该下注多少？"在量化交易的完整框架中，仓位管理与择时信号同样重要——错误的仓位可以将一个优秀的择时策略的绩效完全摧毁。

阿布量化系统的BetaBu模块提供了三种仓位管理策略，分别基于波动率调整（ATR）、凯利公式（Kelly Criterion）和价格百分位（Price Percentile）。这些策略可以独立使用，也可以与买入因子组合，形成不同风险收益特征的策略变体。

## 8.2 仓位管理基类

ABuPositionBase定义了仓位管理的统一接口。核心方法是fit_position(self, factor_object) -> int，返回应购买的单位数量（股数或手数）。基类还定义了全局风险参数：

- g_pos_max：单一头寸的最大仓位比例，默认为0.75（75%）。这个参数限制了单笔交易最多使用可用资金的75%，是硬性的集中度风险控制。

- g_deposit_rate：保证金率，默认为1.0（即无杠杆）。对于期货交易，这个参数可以设置为0.1（10倍杠杆）或更低。

- g_default_pos_class：买入因子的默认仓位管理类。当买入因子没有显式指定仓位管理策略时，使用此类。

## 8.3 ATR仓位管理（ABuAtrPosition）

### 8.3.1 算法原理

ATR仓位管理基于一个核心假设：波动率越高的标的，单笔交易的风险越大，因此应该减少头寸规模；波动率越低的标的，单笔交易风险越小，可以适当增加头寸规模。这本质上是一种"风险平价"（Risk Parity）的思想——让每笔交易的风险贡献大致相等。

### 8.3.2 计算公式

```
std_atr = (atr_base_price / bp) * atr21

atr_wv = max(std_atr, std_atr_threshold)

atr_pos = atr_pos_base / atr_wv

atr_pos = min(atr_pos, g_pos_max)

buy_units = cash * atr_pos / bp * deposit_rate
```

(公式8-1)

其中各参数含义：

- atr_base_price：基准价格常数，默认15元。这是一个将价格水平与ATR进行标准化的参考价格。
- bp（buy_price）：实际买入价格。
- atr21：21日平均真实波幅。
- std_atr_threshold：ATR标准化的下限阈值，默认0.5，防止ATR趋近于零时产生过大头寸。
- atr_pos_base：基础仓位比例，默认0.1（10%）。
- g_pos_max：最大仓位比例，默认0.75（75%）。

### 8.3.3 数学行为分析

std_atr = (15 / bp) * atr21。假设bp=100元，atr21=2元，则std_atr = 0.15 * 2 = 0.30。假设bp=10元，atr21=1元，则std_atr = 1.5 * 1 = 1.50。

atr_pos = 0.1 / max(std_atr, 0.5)。对于100元股票：0.1/0.5 = 0.20（20%仓位）。对于10元股票：0.1/1.5 = 0.067（6.7%仓位）。

注意，10元股票的ATR（1元）在绝对值上小于100元股票的ATR（2元），但相对于自身价格（1/10=10%）远大于100元股票（2/100=2%）。ATR仓位管理正确地识别了10元股票的相对波动率更高，因此给予了更小的仓位。这就是ATR仓位管理的精髓所在——它根据"相对波动率"而非"绝对波动率"来调整仓位规模。

## 8.4 凯利公式仓位管理（ABuKellyPosition）

### 8.4.1 凯利公式的理论基础

凯利公式（Kelly Criterion）由贝尔实验室的John Larry Kelly Jr.在1956年提出，最初用于解决通信信道噪声问题，后被Edward Thorp等人引入赌博和投资领域。凯利公式回答的核心问题是："如果已知一个赌局的胜率和赔率，每次应该下注总资金的多大比例，才能实现长期资金增长率的期望最大化？"

### 8.4.2 计算公式

**源码片段：凯利公式仓位计算**

```python
        """kelly仓位控制管理类初始化设置"""

        # 默认kelly仓位胜率0.50
        self.win_rate = kwargs.pop('win_rate', 0.50)
        # 默认平均获利期望0.10
        self.gains_mean = kwargs.pop('gains_mean', 0.10)
        # 默认平均亏损期望0.05
        self.losses_mean = kwargs.pop('losses_mean', 0.05)

        """以默认的设置kelly根据计算0.5 - 0.5 / (0.10 / 0.05) 仓位将是0.25即25%"""
```


阿布量化系统使用的凯利公式为标准形式：

```
kelly_pos = win_rate - (1 - win_rate) / (gains_mean / losses_mean)
```

(公式8-2)

即：
```
f* = p - q / b
```

(公式8-3)

其中：
- p = win_rate（胜率，默认0.50）
- q = 1 - p（败率，默认0.50）
- b = gains_mean / losses_mean（盈亏比，默认0.10/0.05 = 2.0）

代入默认值：f* = 0.5 - 0.5/2.0 = 0.25，即每次下注总资金的25%。

### 8.4.3 凯利公式的性质

凯利公式的数学性质非常丰富。当b < q/p时，f*为负值，意味着不应该参与这个赌局（期望收益为负）。当b增加（盈亏比改善）或p增加（胜率改善）时，f*增加。当f = f*时，资金的长期对数增长率的期望最大化；当f > f*时，增长率期望下降，甚至可能变为负值（长期亏损）。

在实践中，大多数交易者使用"半凯利"（f*/2）或"四分之一凯利"（f*/4），以降低回撤风险并减少参数估计误差的影响。阿布量化系统的实现中没有直接内置分数凯利，但用户可以通过调整g_pos_max来限制最大仓位，达到类似的效果。

### 8.4.4 与ATR仓位管理的对比

凯利仓位管理和ATR仓位管理代表了两种不同的风险控制哲学。凯利公式基于策略的历史统计特征（胜率和盈亏比），优化的是长期增长率。ATR仓位管理基于当前市场的波动率特征（ATR），优化的是短期风险暴露。在实际使用中，ATR仓位管理更适应市场的实时变化（波动率每天在变），而凯利仓位管理提供了更稳定的框架（胜率和盈亏比变化较慢）。

## 8.5 价格百分位仓位管理（ABuPtPosition）

### 8.5.1 算法原理

价格百分位仓位管理基于均值回复的假设：买入价格越接近历史区间的底部，预期的上涨空间越大，因此应该分配更高的仓位；买入价格越接近历史区间的顶部，预期的上涨空间越小，应该分配较低的仓位。

### 8.5.2 计算公式

```
percentile = scipy.stats.percentileofscore(past_prices, buy_price)
                 # 买入价格在过去N天（默认20天）收盘价中的百分位排位
precent_pos = (1 + (50 - percentile) / 100) * pos_base
             # pos_base默认为0.10
```

(公式8-4)

当买入价格处于第10百分位时（非常便宜）：
```
precent_pos = (1 + 40/100) * 0.10 = 0.14（14%仓位）
```

(公式8-5)

当买入价格处于第90百分位时（非常昂贵）：
```
precent_pos = (1 - 40/100) * 0.10 = 0.06（6%仓位）
```

(公式8-6)

### 8.5.3 适用场景

价格百分位仓位管理特别适合均值回复型买入策略。例如，星期效应策略（ABuFactorBuyWD）的买入逻辑基于"在统计好的星期几，经历下跌后买入"，其本质是均值回复——预期价格从短期低点反弹。使用价格百分位仓位管理，当买入价格确实处于近期低位时给予更多仓位，当买入价格虽然符合条件但并非真正低位时减少仓位，这样的仓位调整与策略的逻辑高度一致。

## 8.6 滑点模型体系

滑点（Slippage）是指交易执行价格与信号触发价格之间的差异。在实际交易中，订单不可能总是按照信号计算时的理论价格成交——存在买卖价差（Bid-Ask Spread）、市场冲击（Market Impact）和时滞（Latency）等因素。滑点模型在回测中模拟这些实际执行成本的近似值，使回测结果更接近实盘表现。

阿布量化系统的SlippageBu模块将滑点分为买入滑点和卖出滑点两大类，各自有独立的基类和实现。

## 8.7 买入滑点模型

### 8.7.1 均价买入滑点（ABuSlippageBuyMean）

默认的买入滑点模型，以当日均价近似实际成交价格：

```
buy_price = mean([high, low])
```

(公式8-7)

这个公式假设买入订单在当日高低价的正中间成交。实际上，这不是最理想的假设（理想的买入价格应靠近低价，而非均价），但它是一个保守的估计——使用均价而非信号触发价（通常为收盘价）意味着买入成本包含了约半个日振幅的滑点。

开盘下跌过滤器：如果today.open / today.pre_close < (1 - g_open_down_rate)，默认g_open_down_rate=0.07（即低开7%以上），放弃该订单（返回np.inf）。这模拟了大幅低开情况下的流动性稀缺——在极端低开行情中，买单可能无法成交，或成交价格远低于预期。

### 8.7.2 涨停板处理（slippage_limit_up装饰器）

slippage_limit_up装饰器专为A股市场的涨停板机制设计，模拟了涨停板时的成交概率和价格发现：

1. 涨停检测：p_change >= 10（涨幅达涨停板）且high == close（收盘封在涨停价），确认涨停。

2. 成交概率模拟：使用np.random.binomial(1, limit_up_deal_chance)进行一次伯努利试验，模拟排队能否成交。如果high==low（全天一字板/集合竞价封板），成交概率降至正常概率的20%。这反映了集合竞价封涨停时排在前面的买单数量巨大，后到者几乎不可能成交的实际情况。

3. 价格发现：如果成交，通过np.random.choice从当日价格序列（low到high的等分序列）中进行加权随机抽样。权重由np.linspace(0, 1, N)生成——线性递增的权重意味着价格越靠近涨停价，被选为成交价的概率越高。这模拟了排队优先级——在涨停板上挂的买单需要等待卖单出现，越早挂单（越靠近涨停价）越可能成交。

## 8.8 卖出滑点模型

### 8.8.1 均价卖出滑点（ABuSlippageSellMean）

卖出滑点的默认模型与买入对称：sell_price = mean([high, low])。与买入不同的是，卖出滑点没有开盘下跌过滤器。这是因为卖出通常由止损信号触发，在不利行情中应该优先确保成交（哪怕价格稍差），而非因滑点过大而放弃离场。

### 8.8.2 跌停板处理（slippage_limit_down装饰器）

跌停板处理与涨停板处理逻辑镜像：检测p_change <= -10且low == close，伯努利试验模拟成交概率，加权随机抽样模拟价格发现。与涨停的向上权重不同，跌停的价格发现使用从高价到跌停价的递减权重——越靠近跌停价，被选为成交价的概率越高。

## 8.9 保证金与杠杆

系统通过g_deposit_rate参数支持保证金交易和杠杆控制。对于期货市场，min_deposit字段指定了每个期货合约的最低保证金比例：

buy_units = cash * position_size / buy_price * (1 / deposit_rate)

例如，如果deposit_rate=0.1（10%保证金，即10倍杠杆），position_size=0.2（20%仓位），cash=100000元，buy_price=50元，则：

buy_units = 100000 * 0.20 / 50 * 10 = 4000股

而在无杠杆的股票市场（deposit_rate=1.0），同样的参数仅买入400股。杠杆放大了收益，同时也放大了风险——系统通过仓位管理公式中的position_size已经隐含了对杠杆风险的考量。

## 8.10 交易成本模型

### 8.10.1 佣金计算

ABuCommission模块为不同市场提供了差异化的佣金计算模型：

| 市场 | 佣金计算方式 | 最低收费 | 备注 |
|------|-------------|---------|------|
| 美股 | 交易股数 × $0.01 | $2.99 | 模拟盈透证券(Interactive Brokers)等主流美股券商 |
| A股 | 印花税(卖方0.1%) + 佣金(买卖各0.025%) | 5元佣金 | 印花税仅在卖出时收取 |
| 港股 | 佣金0.2% + 印花税0.1% | 因券商而异 | — |
| 加密货币 | 交易金额的0.2% | — | 模拟主流交易所费率 |
| 中国期货 | 每手固定佣金 | — | 由期货合约的commission字段指定 |

### 8.10.2 交易单位的取整

订单执行时，买入数量必须向下取整到该市场最小交易单位的整数倍：

| 市场 | 最小交易单位 | 说明 |
|------|-------------|------|
| 美股 | 1股 | 按股交易 |
| A股 | 100股 | 1手=100股 |
| 港股 | 因标的而异 | 通过ABuHkUnit查询（如100股、500股、1000股不等） |
| 期货 | 1手 | 按合约交易 |
| 加密货币 | 小数位 | 支持非整数数量（如0.001 BTC） |

取整操作可能导致实际投入资金略低于计算值——这部分"剩钱"留在现金账户中，不会产生收益。
