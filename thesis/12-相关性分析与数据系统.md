# 第十二章 相关性分析与辅助系统

## 12.1 相关性分析系统（SimilarBu）

SimilarBu是阿布量化系统中实现"配对交易"（Pairs Trading）和"相似标的发现"的模块。其核心思想是：在全市场范围内找到与目标标的走势高度相似的标的，利用它们之间的统计关系（相关性、协整[^corr_1]性）构建交易信号。

### 12.1.1 相关系数计算（ABuCorrcoef）

系统实现了四种相关系数的计算方法：

**皮尔逊相关系数（E_CORE_TYPE_PEARS）：**

数学公式：
```
corr(X, Y) = cov(X, Y) / (σ_X * σ_Y)

           = Σ((x_i - x̄)(y_i - ȳ)) / √(Σ(x_i - x̄)² * Σ(y_i - ȳ)²)
```

(公式12-1)

这是最常用的线性相关系数，衡量两个变量之间线性关系的强度。通过numpy.corrcoef实现。对异常值敏感——一个极端数据点可能显著改变相关系数。

**斯皮尔曼秩相关系数（E_CORE_TYPE_SPERM）：**

对数据进行排名（rank）后再计算皮尔逊相关系数：
```
corr_spearman = corr_pearson(rank(X), rank(Y))
```

(公式12-2)

斯皮尔曼相关系数衡量的是单调关系（不限于线性）。对异常值不敏感——因为排名消除了异常值对数值的极端影响。实现的优化：使用scipy.stats.rankdata进行排名，然后使用numpy.corrcoef计算秩的相关系数，跳过了scipy.stats.spearmanr中的p值计算（在大规模全市场相关性计算中，p值不是必需的），提高了计算效率。

**符号相关系数（E_CORE_TYPE_SIGN）：**

先将序列量化为方向符号（+1、0、-1），再计算皮尔逊相关系数：
```
corr_sign = corr_pearson(sign(X), sign(Y))
```

(公式12-3)

这种方法只关心方向一致性，不关心幅度。例如，如果X和Y每次都同涨同跌（但涨跌幅度不同），符号相关系数接近+1；如果X涨的时候Y总是跌（无论幅度），符号相关系数接近-1。这在捕捉"方向性共振"而非"幅度性共振"时非常有用。

**滚动时间加权相关系数（E_CORE_TYPE_ROLLING）：**

将序列划分为60个交易日的重叠窗口，对每个窗口计算皮尔逊相关系数，然后使用时间权重（近期窗口权重更高）进行加权平均：
```
rolling_corr = Σ w_t * corr(window_t) / Σ w_t
```

(公式12-4)
权重w_t由np.linspace(0, 1, N_window)生成线性递增序列，归一化为和为1。

这种方法的核心优势是：近期相关性变化对最终值的影响大于远期变化。如果两只股票在过去高度相关，但最近开始背离（相关性下降），滚动时间加权相关系数会及时反映这一变化，而简单的全期相关系数可能仍然显示高相关性。

常数序列的处理：如果X或Y为常数（所有值相同，方差为0，相关系数未定义），回退到方向一致性比例：(x == y).sum() / len(x)。

### 12.1.2 全市场相似度搜索（ABuSimilar）

_all_market_cg函数构建了全市场的百分比变化（p_change）矩阵。这是一个巨大的DataFrame——每列是一个标的，每行是一个交易日，值为当日涨跌幅。假设A股全市场约4000只标的、回看期252个交易日，这个矩阵的大小约为252×4000。

_make_kl_df_create通过多进程并行（Parallel/delayed）获取所有标的的K线数据，提取p_change列，拼接为全市场矩阵。

_handle_market_change_df使用目标标的的p_change序列（benchmark_df）与全市场矩阵进行相关性计算。结果是按相关系数降序排列的标的列表——排在最前面的是与目标标的走势最相似的标的。

时间框架控制提供了三种方式：
- find_similar_with_se：使用精确的起止日期
- find_similar_with_folds：使用年数从当前日期向前回推
- find_similar_with_cnt：使用精确的交易天数

multi_corr_df方法同时计算皮尔逊和斯皮尔曼两种相关系数矩阵。在ABuTLSimilar中，两种相关系数的结果通过排名求和（rank_corr_sum）进行组合：对每种方法计算目标标的与每只其他标的的相关系数后按降序排名，然后将两种方法的排名求和，排名总和最小的标的即综合相关性最高的标的。

### 12.1.3 协整检验与差异投票

从排名最高的相似标的中，ABuTLSimilar使用Engle-Granger协整检验筛选具有统计显著协整关系的配对标的。协整（Cointegration）是两个非平稳时间序列之间存在长期均衡关系的统计概念。即使两个价格序列各自都是单位根过程（随机游走），如果它们的线性组合是平稳的，那么它们之间存在协整关系。

Engle-Granger协整检验：

1. 对Y_t和X_t做OLS回归：Y_t = α + βX_t + ε_t

2. 对残差ε_t进行ADF（Augmented Dickey-Fuller）单位根检验

3. 如果拒绝"ε_t有单位根"的原假设（即p值≤0.38），认为存在协整关系

p值阈值0.38的设置比通常的0.05宽松得多。这是有意为之——在金融数据中，过于严格的阈值可能导致协整关系难以通过检验（金融数据的噪声特性），而0.38提供了一个"存在关系但不一定显著"的筛选标准。

### 12.1.4 相似度绘制

ABuSimilarDrawing的draw_show_close函数对相似标的的价格序列应用Z-score标准化：
```
z_score = (price - mean(price)) / std(price)
```

(公式12-5)
标准化后所有序列以0为中心、标准差为1，使得不同价格水平的标的（高价股和低价股）可以在同一张图上进行视觉比较。这解决了"特斯拉（$250）和诺亚财富（$25）如何放在一张图上比较走势"的问题。

### 12.1.5 相似度缓存

ABuSimilarCache使用HDF5文件存储全市场相关性计算结果。缓存的键由symbol、cmp_cnt、n_folds、start、end和corr_type的组合生成。全市场相关性计算是极其昂贵的操作（需要计算目标标的与数千只其他标的的相关系数），缓存的引入避免了重复计算。

## 12.2 数据爬取系统（CrawlBu）

CrawlBu实现了从雪球网（xueqiu.com）爬取股票基础信息的功能。这是系统进行数据初始化的第一步——在开始量化分析之前，需要知道每个市场有哪些标的以及它们的基本信息。

### 12.2.1 数据爬取架构

ABuXqApi定义了雪球网的API端点URL模板，按市场类型（A股/港股/美股）和数据类型（行业分类/股票列表）参数化构建。

爬取采用Selenium WebDriver自动化浏览器（Chrome）：
- StockListCrawlBrower：导航至股票列表页，设置最大分页数（减少翻页次数），遍历每一页，通过XPath提取股票名称和代码。
- StockInfoListBrower：对每只股票，访问其详细资料页，通过XPath提取公司名称、交易所、行业分类、财务指标和联系方式等信息。单只股票的信息保存为一个CSV文件。

爬取结果通过ABuXqFile模块进行：
- 合并（merge_stock_info_to_stock_list）：将分散的个股信息CSV合并到主股票列表CSV
- 列名修复（fix_xq_columns_name）：使用columns_map字典将中文列名映射为英文列名（如"股票代码"→"symbol"、"行业"→"industry"）

ABuXqConsts定义了20+个字段的列名映射，涵盖symbol、market、exchange、industry、company_name、pe_ratio、pb_ratio、turnover_rate、total_assets、market_value等多个维度。

### 12.2.2 爬取流程

完整的爬取流程（update_all）为：

1. crawl_stock_code → 获取所有股票代码

2. crawl_stock_info → 获取每只股票的详细信息

3. merge_stock_info_to_stock_list → 合并为完整列表

4. fix_xq_columns_name → 修复列名

对于大规模爬取（如全部A股约4000+只股票），使用了批次处理和多进程加速。

## 12.3 Web服务器与前端（server.py + static/）

阿布量化系统包含一个基于Flask的轻量级Web服务器（server.py），它桥接了abupy核心库和浏览器前端界面。

server.py的功能包括：
- 启动Flask HTTP服务器
- 提供RESTful API，接收前端请求并转发到abupy的相应功能模块
- 返回JSON格式的分析结果

static/目录包含前端页面：

backtest.html：回测操作界面，允许用户通过Web界面配置回测参数（标的、时间范围、策略选择），查看回测结果图表。

dash.html：量化仪表盘，汇总展示多个关键指标。

index.html：系统主页。

monitor.html：实时监控页面，可能用于展示live_monitor.py的实时数据。

echarts.min.js：使用Apache ECharts（百度开源的可视化库）作为前端图表引擎，支持交互式K线图、资金曲线和统计图表。

## 12.4 macOS桌面应用（QuantDesk.app）

QuantDesk.app是系统的macOS桌面应用版本。由于系统使用Python作为核心语言，桌面应用采用了以下技术栈：

- Electron[^corr_6]框架（通过package.json确认）作为桌面壳，嵌入Web前端
- Python后端通过Flask服务器提供API
- 前端使用HTML/CSS/JavaScript + ECharts

dist/目录包含打包好的QuantDesk.app（macOS应用包）、QuantDesk.dmg（安装镜像）和QuantDesk.iconset（应用图标集）。应用图标集包含了从16×16到512×512的多种分辨率图标，支持Retina显示屏。

build-macos-app.ts脚本（TypeScript）负责将整个项目打包为macOS应用。

## 12.5 实时监控系统（live_monitor.py + radar/）

live_monitor.py和radar/目录代表了系统从"离线回测"向"实时辅助"的拓展：

radar/news_fetcher.py：新闻获取模块，从外部源获取市场新闻。

radar/sentiment.py：情感分析模块，对新闻进行情感极性分析（正面/负面/中性）。

radar/risk.py：风险评估模块，实时监控持仓风险。

radar/scorer.py：评分模块，对交易标的进行实时评分。

这些模块构成了"雷达系统"——持续扫描市场信息，为实盘决策提供参考信号。

## 12.6 预测模块（predict/）

predict/目录包含了基于机器学习的预测实验：

features.py：特征工程，从原始市场数据中构建用于ML模型的特征。

train.py：模型训练，使用历史数据训练预测模型。

walkforward.py：前向验证[^corr_7]（Walk-Forward Validation），将数据按时间顺序划分为多个训练/测试窗口，逐步推进，模拟真实交易中"随着新数据到来逐步更新模型"的场景。与随机交叉验证不同，前向验证严格遵循时间顺序，不会使用未来信息。

## 12.7 教程系统（abupy_lecture/ + ipython/ + python/）

阿布量化系统附带了一套从入门到进阶的完整教程体系：

abupy_lecture/：32个Jupyter Notebook，编号从0到32，覆盖了环境部署、择时策略开发与优化、选股策略、回测度量、多市场回测（A股/港股/美股/期货/加密货币）、机器学习应用、UMP裁判系统等全部功能模块。

ipython/：配套《量化交易之路》书籍的14个Notebook，从Python基础到机器学习的高级应用。

python/：配套示例的Python脚本，包括股票数据分析的各个阶段示例。

这些教程不仅是文档，还是可执行的Notebook——用户可以在Jupyter环境中逐单元运行代码，直接看到结果和图表。

[^corr_1]: **协整（Cointegration）**：由Engle和Granger在1987年提出的统计概念。两个或多个非平稳时间序列，如果存在一个线性组合是平稳的，则称它们之间存在协整关系。在金融中，协整通常解释为"长期均衡关系"——即使两个价格各自随机游走，它们之间的价差倾向于回归到一个长期均值。

[^corr_2]: **ADF检验（Augmented Dickey-Fuller Test）**：检验时间序列是否存在单位根（非平稳性）的统计检验。原假设为"序列有单位根（非平稳）"，如果检验的p值足够小（通常<0.05），则拒绝原假设，认为序列是平稳的。

[^corr_3]: **Z-score标准化**：将数据转换为均值为0、标准差为1的分布。公式为z = (x - μ) / σ。标准化后的数据去除了量纲（单位）和位置（均值）的影响，便于不同量级的数据在同一尺度上比较。

[^corr_4]: **XPath**：XML Path Language，一种用于在XML/HTML文档中定位节点的查询语言。在Selenium爬虫中，XPath用于精确定位网页中的元素（如表格行、链接文本）。

[^corr_5]: **Selenium WebDriver**：浏览器自动化框架，可以通过代码控制浏览器执行网页导航、表单填写、元素点击等操作。在爬虫中，用于处理需要JavaScript渲染的动态网页（普通HTTP请求无法获取JS动态生成的内容）。

[^corr_6]: **Electron**：GitHub开发的桌面应用框架，使用HTML、CSS和JavaScript构建跨平台桌面应用。它通过嵌入Chromium浏览器引擎和Node.js运行环境，使Web技术可以用于开发桌面软件。

[^corr_7]: **前向验证（Walk-Forward Validation）**：时间序列模型评估方法，将数据按时间顺序划分为多个窗口，每个窗口内用历史数据训练、用未来数据测试，然后窗口向前滑动一步。这种方法模拟了真实交易中"用已知数据训练→预测→接收新数据→重新训练"的循环，比随机交叉验证更适合金融时间序列。
